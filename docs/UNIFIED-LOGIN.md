# 统一登录与公网转发

[English](UNIFIED-LOGIN.en.md) · 简体中文

v0.1.20建立统一登录；下列用户规则已随单一工作台更新。边缘网关保留TLS和固定转发，用户会话、应用入口、业务授权及旅行分享均由源站处理。平台入口与前后端关系统一见[平台手册](PLATFORM.md)。

## 用户入口

- 统一地址为安装配置的规范 HTTPS 入口；未登录进入Praxis登录页，不再弹Basic密码框。
- 每个有效Praxis账号都进入工作台，只展示获准应用/项目。例如，仅授予听校入口的账号在工作台只看到听校，不能访问PRD或其他应用；这是应用级范围，不代表项目/任务隔离。
- 浏览器复用同域安全会话，点击“退出”撤销该会话。管理员第一方浏览器直接使用本人当前业务权限，其他业务委托与外部agent授权仍按具体范围确认。
- agent使用`/mcp`及OAuth授权码+PKCE/Bearer，授权、续期和撤销不经过第二套网关密码。
- 原HTTP4321入口跳转规范HTTPS；其他原始应用端口限制在本机。当时的切换没有包含旧浏览器的本地数据。

## 身份与授权

身份继续保存在既有身份数据库，`auth_web_access`保存应用ID、PRD许可及期限。有效原生浏览器身份默认有工作台外壳，旧workbench开关不再阻断桌面；每次应用/PRD访问仍重查入口权限。入口到期收回内容但不使身份提前退出；缺策略显示空桌面，损坏策略失败关闭。家庭/公司空间管理员不自动获得整站应用或平台管理权，全局状态仅授权给平台管理员。

应用入口许可与业务资源/动作授权分开；普通业务Bearer不能进入旧应用整库页面，旧Basic密码也不能建立Praxis身份。登录、OAuth和业务API仍由业务服务自行鉴权。

日常账号与应用入口通过工作台的「设置」页面配置；字段、会话与授权有效期、查看能力和维护引导详见[身份与授权](BUSINESS-AUTH.md#51-网页入口权限与一次登录)，本转发手册不重复维护另一套配置流程。

## 运行边界

私有业务配置增加：

```json
{
  "webGateway": {
    "enabled": true,
    "originHost": "localhost",
    "shareManifestFile": "/private/praxis/web-gateway/travel-shares.json"
  }
}
```

`originHost`为固定的旧应用Host，业务服务Host仍使用规范HTTPS issuer。分享目录仅保存授权清单和其锁/原子更新文件，目录700、清单600；源站网关只读挂载该目录，身份库、适配器密钥和 Docker socket 保留在网关容器之外。启用信件与个人资料时，为两个阅读器分别配置只读文档挂载。

启用后，私有Compose覆盖将`praxis-public`以主机网络运行在14321，原始应用发布端口和业务监听均限制为回环。网关仅能转发到固定本机服务，覆盖HTTP、图片条件请求、范围请求、SSE与WebSocket。长连接每5秒及到期时重验入口权限；业务写入仍遵循业务服务与适配器自身的授权、版本和幂等规则。

图片保留ETag/Last-Modified和304，私有图片每次重验证会话；其他私有响应不缓存。代理剥离伪造内部身份头和旧应用返回的Set-Cookie，不能由应用覆盖平台身份。分享按原能力URL、指定行程、期限和实时撤销逐请求检查，拒绝查询参数、写入和升级。

## 切换与恢复

原统一登录切换先部署源站守卫与回环端口，验证匿名、所有者、受限账号及 OAuth。确认固定源站设置后，重载中继，重建边缘入口以移除旧用户文件挂载，最后停用旧分享校验服务。其他服务和证书保留原配置。当前安装使用私有 Compose 定义及蓝绿切换步骤。[受管部署](MANAGED-DEPLOYMENT.md)

源站不可用返回503，不回退到匿名后端。旧Basic模式的检查脚本不能用来判断新模式，因为其预期认证方式不同。当前回归运行 `npm test`。原切换还验证了边缘转发和真实浏览器登录，使用隔离身份与合成内容。实际入口另以匿名重定向、受限账号、元数据及撤销检查验证，维护者不执行真实业务工具。

恢复配置保存在私有目录；恢复旧中继规则时必须同时匹配源站监听和路由，不能在原始应用端口仍对外开放时撤销认证。源码回退不覆盖身份数据库、授权预算或业务记录。
