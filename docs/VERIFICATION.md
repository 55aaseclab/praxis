# Praxis 验证方案与结果登记

历史验证基线：2026-11-12 · v0.1.17。以下按当时的版本分别登记源码、隔离测试、授权客户端、云端往返和物理手机结果。

[English](VERIFICATION.en.md) · 简体中文

本文件承接 [PRD](PRD.md) F24–F31 与[路线图](ROADMAP.md)，定义准备、执行者、断言、证据、清理和失败分类。v0.1.14 的文档基线和 v0.1.17 的实测结果分别列在第 13、16 节。发布后的服务需要对当前版本重新验收。

接口路径、方法、工具名称和字段以实施后发布的 OpenAPI/MCP 合同为准。下文使用业务语义描述步骤，不把候选工具或设计中的端点写成已有服务。

## 2. 开发与使用分离、执行主体与测试数据

按 PRD 1.4，开发与使用分离按身份与通路执行。同一种模型也必须建立独立的开发/业务会话、身份、凭据和环境，审计区分两侧；禁止从维护会话继承管理员权限来运行业务演示。平台管理员使用产品也通过独立业务身份。

| 主体 | 允许执行 | 本轮边界 |
|---|---|---|
| 当前维护代理 | 修改授权的代码、文档、测试与必要配置；使用临时合成夹具运行自动测试；核验脱敏证据 | 不读取私人正文，不经 CLI、SQL、文件、curl、管理 token 或强权子 agent 填充、修改或清理线上业务记录。 |
| 外部业务 agent（包括 Paseo Codex/OpenCode 等客户端） | 使用独立业务身份，经获授权 MCP 创建、读取、修改、完成、提交和清理验收记录；使用自身 shell、文件、联网工具配置连接及完成内容任务 | 保留正常客户端工具；不继承平台维护身份和服务端管理凭据。业务资源/动作权限由服务端校验。 |
| 手机 App 用户与客户端 | 经正式授权流程登录、授予/撤销范围，在真机 App 发出业务请求 | 不把密码、原始 token 或 owner 会话交给模型。 |
| 可信只读验收器 | 在服务端真源计算版本、数量、结果断言与安全摘要，生成脱敏审计 | 不向维护代理输出请求/响应正文、附件、凭据或恢复材料。 |

业务验收使用明确的测试空间及带 `run_id` 的合成业务记录，或用户明确指定的测试记录。记录从创建到清理均由业务 agent 经 MCP 完成；维护代理不能先在后端造记录再让 agent 读取。

跨主体负向样本由各自具有有限授权的业务身份经 MCP 创建，测试主体与会话分开。不给受限验收身份长期全局权限来准备样本，不用私人存储作为测试库。

每轮登记用户、客户端、空间、资源集合、动作、生效/到期与撤销状态。至少有个人 A/B、家庭 A/B、公司 A/B、已分配/未分配任务，以及读权限/写权限的对照。向负向测试执行者只提供必要的合成资源标识，不交付未授权正文。

## 3. C01：独立业务身份与客户端能力

外部内容 agent 保留其 harness 的正常工具，包括 shell、本地文件、浏览器/联网及 MCP/OAuth 配置能力。业务身份与授权须和平台维护权限分开，不能以禁用客户端工具代替鉴权。Praxis 及各应用在服务边界校验账号、资源与动作权限，客户端能发送任意 HTTP 请求也不能绕过。客户端可以使用自己的工作文件与凭据；平台管理员凭据、服务端数据及恢复密钥不作为业务接入权限交付。

1. 通过 Paseo 主机/profile/provider/model 发现确认用户指定的实际客户端与模型，不固定要求 Codex，不猜测配置。
2. 以独立业务会话启动正常 agent，记录 `{serverId, workspaceId, agentId}`、provider/model、工具与凭据归属；不额外加入 shell/文件/联网禁用配置。
3. 验证客户端能够配置 MCP、发起 OAuth、让用户登录并选择授权范围，随后按实际身份发现应用与工具。缺少连接配置时应完成配置，不把禁用工具作为接入前提。
4. 使用获准合成资源验证服务端资源/动作隔离、越权拒绝、撤销和无副作用；客户端可使用正常 HTTP 工具，所有受保护入口仍必须鉴权。
5. 不以工具被禁用、另一个 worktree 或一段提示词证明鉴权通过；保留实际用户同意、服务端决策、客户端回读与拒绝证据。

客户端按正常 OAuth 流程管理自己的凭据，不在提示词或验收输出中暴露原始 token，不使用平台 owner/运维凭据代替用户委托。历史用例中更严格的挂载/出口限制只描述当时环境，不成为新内容 agent 的默认要求。

## 4. C02/I01：合同、发现与统一业务语义

C02 核验实际 MCP 版本、传输方式、HTTPS 可达性、客户端能力及授权流程。先连接和发现，再以实际合同调用；工具集合只含当前身份应获得的业务能力，未知或越权调用仍由服务端拒绝。

公开 OAuth 元数据、协议发现和明确公共 schema 可以匿名访问；公共结构不得夹带私人记录、内部路径或凭据。受保护的业务 schema、资源描述与工具结果按授权处理，不能一概禁止公共发现，也不能借公共发现暴露业务数据。

I01 用临时合成夹具验证网页、统一 API 和 MCP 复用同一业务规则、版本与幂等语义，符合 owning app 的既有校验。Reminder 保留 schema v2 兼容；TingProof 复用任务真源。多协议不能各维护一份业务数据。

无效参数、额外代码/SQL/路径字段、异常版本及未知资源不伪装成功；返回实际结果、保存版本与审计关联号。维护代理只运行夹具测试；实际验收数据仍由业务身份操作，直接 API 的负向检查由受限客户端/验收器完成。

## 5. R01：Reminder 首个远程 MCP 闭环

在 C01/C02 前提通过后，由同一受限 Codex 业务 agent 执行：

| 步骤 | 业务操作 | 必须证明 |
|---|---|---|
| 列表 | 查询当前授权范围 | 只出现授权记录；空列表不掩盖权限或服务异常。 |
| 创建 | 经 MCP 创建带本轮标识的合成事项 | 一条实际保存结果、资源伪名、初始版本与审计关联号。 |
| 回读 | 经 MCP 列表/读取刚创建事项 | 真源版本及内容断言与创建结果一致。 |
| 更新 | 提交期望版本并修改合成字段 | 只修改目标，版本前进，回读确认持久化。 |
| 完成 | 执行完成动作并回读 | 状态真实变化，仍归原用户/空间。 |
| 限定删除 | 仅删除本轮创建且获准删除的事项 | 不影响其他记录，结果符合删除及幂等合同。 |

自然语言“已完成”和一次工具成功响应均不是持久化证明。业务 agent 回读与服务端独立只读断言必须能关联；维护代理只看脱敏跟踪、版本、数量和摘要。

## 6. T01：TingProof 外部任务与资源访客

由任务拥有方的有限业务身份经 MCP 准备合成任务，授予外部访客“指定任务资料读取＋校正结果提交＋期限”，不授予全项目访问。

访客读取获分配资料、提交合成校正、回读提交结果；真源确认结果归原空间并记录发起人和实际客户端。另一个未分配任务以及同项目其他资源均作为负向对照。

覆盖项目列表、搜索、任务正文、附件、音频、下载/导出和提交等实际存在的入口；不能只过滤一个任务查询。既有 `tingproof-worker` 应用账号不算资源级权限证明。

撤销/到期后不能继续读取或提交；已合法提交的校正结果仍归原空间保留。仅清理本轮合成资源，不清理用户原项目。

## 7. A01–A05：权限正反例

每个拒绝用例同时验证“服务端拒绝”和“业务无副作用”。由可信只读验收器比较目标前后版本、数量及摘要；维护代理不打开目标正文。

| ID | 执行与对照 | 通过标准 |
|---|---|---|
| A01 | 个人 A 正常操作自己的测试记录，尝试个人 B 的记录 | A 的授权动作成功；跨个人读取/写入拒绝，列表/搜索不泄露 B 的信息。 |
| A02 | 家庭/公司成员操作获准资源，再访问其他空间及成员个人资料 | 加入家庭/公司不自动共享个人数据；跨空间拒绝。空间管理员可经获准业务接口管理本空间成员/共享/委托，但仍无平台代码权，不能改变服务端权限判定或自行升为平台管理员。 |
| A03 | 外部访客访问已分配任务，再访问未分配任务和同空间其他资源 | 授权按任务/资源生效，不能凭应用登录或同空间身份放行。 |
| A04 | 读权限尝试写入/删除/导出，检查批量、附件/音频、缓存及受保护 schema | 缺少相应动作时拒绝；列表、分页、聚合、下载产物均不泄露或扩大范围。公开 schema 按 C02 处理。 |
| A05 | 伪造用户/角色/空间/客户端/资源 ID，尝试高权限工具、原始文件及直接 API 旁路 | 服务端可信身份和委托交集仍生效；业务 MCP 不开放服务端 shell、SQL、任意文件、代码提交、部署或备份能力，客户端自身正常工具不受此条禁用。 |

受限请求不能仅因模型填入另一个身份而改变授权。有效权限为用户当前权限、客户端委托、空间/资源及动作约束的交集。

错误按已发布合同区分：未认证通常为 401、权限不足通常为 403；未知/无权资源采用一致表现防止枚举。版本冲突为 409 或合同明确的等价冲突；内部错误和失败不返回私人正文、秘密或内部路径。

## 8. A06：到期、撤销与在途任务

先以有效授权成功调用，再撤销、退组或等待专用测试 grant 到期，记录生效事件与请求时间，验证：

- 原连接、重连、刷新授权及其他客户端复用旧凭据均不能恢复权限；
- 缓存读取、条件请求、资源 URI、附件及下载入口不能绕过当前授权；
- 已建立的订阅关闭，后续事件不再广播；
- 队列、后台业务任务和自动重试在执行、提交及交付前按当前授权检查，不以旧连接继续写入或导出。

按 PRD 承诺的撤销时限判定，不能靠等缓存自然过期证明即时撤销。已经合法交付客户端的内容无法保证追回，报告应明确此限制。

## 9. S01–S05：家庭实时协作、冲突与异步副本

由两个独立获准业务身份、两个客户端通过同一业务接口执行；维护代理不直接改文件制造变化。

| ID | 场景 | 通过标准 |
|---|---|---|
| S01 | 两位成员互见共享事项的创建、修改、完成 | 业务保存后才发布事件；指定合成规模与正常网络下，服务端确认至另一客户端可见目标 ≤2 秒，记录实测环境/延迟，不当作跨网络 SLA。 |
| S02 | 两客户端基于同一版本修改同一记录，另测不同记录 | 同记录后提交者得到 409/明确冲突，草稿保留，无静默覆盖；不同记录可分别保存。冲突后重读再提交成功。 |
| S03 | 已提交但响应丢失后以相同幂等键重试；相同键改输入 | 同一动作仅生效一次；不同输入按合同拒绝。保留实际生效次数与请求关联。 |
| S04 | 断线重连、服务重启、旧游标及过期游标；再撤销订阅权限 | 按游标补齐或重读当前授权数据，无跨空间广播；撤销后旧连接/恢复队列不泄露或写入。 |
| S05 | 云端不可达或限流，随后恢复 | 本地业务与家庭推送正常；事件触发一致快照/持久待同步队列不丢失，短时变化可合并；恢复后补传并校验，状态不虚报已同步。 |

“已保存”与“已同步”分别核验。业务 `spaceId` 与存储 `workspaceId` 映射及覆盖范围可审计，不把整份私有备份当共享接口。S05 使用可控故障与合成副本，真实云端另见 B01。

首版离线只读与离线状态需要准确；离线写队列、多设备自动合并为 P2，不作为首批已交付能力。

## 10. M01–M03：独立的真实手机 App 验收

F31 与 Paseo Codex 是两条独立必过链路。电脑客户端、Qwen Code、模型 API、模拟器、手机浏览器打开网页、手工复制结果或 Paseo 手机界面转发桌面 Codex，均不能代替手机第三方 agent App。

| ID | 执行方法 | 通过标准 |
|---|---|---|
| M01 | 优先核查用户实际豆包 App 的版本、账号准入、插件/Skill 分发、登录及 OAuth/工具能力 | 在物理手机完成正式连接与本人身份绑定，展示并授予指定空间/任务、动作及期限；不把原始 token/密码交模型。 |
| M02 | 在手机 App 对话发出合成记录创建、修改及读回请求 | 真实调用远程业务能力，与获准工作台客户端看到同一保存结果；手机操作、客户端身份、MCP 请求和真源断言可关联。 |
| M03 | 尝试跨范围动作，再撤销手机客户端授权并重试 | 越权和撤销后服务端拒绝，无副作用；通过 MCP 清理手机测试记录。 |

记录 App 名称/发布方/版本、系统版本、物理设备、网络条件、账号伪名及实际接入路径。保存必要脱敏录屏/截图与时间、请求关联号；模型回答“已完成”不能单独证明调用。

普通 App 可自定义 MCP 不是默认假设。按 [PRD F31](PRD.md) 的官方依据重新核实具体账号与手机版本，平台/API 支持不代表普通 App 已开放。

豆包准入或能力受阻时记录原因和证据，继续自有 API/MCP，并选择经核实可用的其他真实手机 agent App 跑相同用例；至少一个真实手机 App 必须通过。其他 harness 可做兼容性补充，桌面千问/Qwen Code 不计手机通过。

新授权入口不得外发管理员/网关 owner 口令，也不能导致既有页面、API、媒体或应用入口匿名绕过。

## 11. 证据格式与维护代理核验

每条结果记录至少包含以下字段；正文、认证头和秘密均不进入通用审计或 Git：

| 字段 | 内容 |
|---|---|
| `run_id`、`case_id`、`requirement` | 本轮、用例及 F 编号。 |
| `caller`、`build` | 实际执行客户端/provider/会话及服务构建版本、MCP/合同版本。 |
| `principal`、`scope` | 用户、业务服务身份、客户端、空间、grant 和资源的稳定伪名；动作及有效期。 |
| `trace`、`decision` | 请求/审计/事件或后台任务关联，允许/拒绝及原因类别。 |
| `version`、`digest` | 真源前后版本、受影响数量、结果断言与安全摘要，不能仅是 agent 自述。 |
| `expected`、`actual`、`timing` | 预期、实际、开始/结束/撤销时刻及需要时的观测延迟。 |
| `cleanup`、`result` | 清理状态/剩余资源伪名，以及未执行、前提未就绪、运行中、通过或失败。 |

维护代理仅核验脱敏跟踪、服务端审计、真源摘要及独立只读断言，不查看 live payload。敏感低熵内容不使用可猜测的裸哈希替代保密；使用可信服务生成的带密钥摘要或等效安全标识，维护代理不取得摘要密钥。

证据保留必要关联即可，不提交私人正文、原始请求/响应、附件、秘密值、恢复材料、私有截图或可复用下载链接。截图先脱敏，审计与证据自身也受访问和保留范围约束。

## 12. X01 清理、D01/B01 独立前提与失败处理

X01：所有线上测试记录由业务 agent 经 MCP 删除或恢复，只限当前 `run_id` 创建且获准处理的资源。通过业务接口核验剩余数量、任务和导出产物状态，形成清理回执。
