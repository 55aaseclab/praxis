# Praxis 运维技能

[English](SKILL.md) · 简体中文

本技能用于维护 Praxis 平台和应用的代码、产品文档、schema、配置及测试。Praxis 向外部智能体提供业务工具；平台内部不运行智能体。当前维护智能体只修改授权范围内的代码、文档、测试及必要配置，**不得创建、修改或删除真实业务记录**。业务用户及其外部智能体通过限定范围的业务 API/MCP 操作数据，无平台源码或宿主机权限。

开发和使用是不同的角色。两种角色即使使用同一模型，也须分别建立会话、身份、凭据、环境和审计记录。不得自动把高权限维护会话改作业务会话。平台管理员实际使用产品时，也要采用独立的业务身份。

改进已有应用应从其既有界面入手。开发界面的授权不包含操作线上业务记录，也不赋予业务智能体源码权限。

## 确定归属

从技能目录的 `../..` 找到工作区根目录，阅读[当前需求](../../docs/PRD.md)和[路线图](../../docs/ROADMAP.md)。检查受影响应用的维护说明、需求、package 脚本、CLI 帮助和数据合同。从仓库确认实际路径和命令。

平台负责发现、工作台入口及跨应用协调。各应用独立于 Praxis 和旧 Books 前端运行，自主管理行为和数据真源。工作台的链接不转移数据归属。项目参考文档与可运行应用分别管理。Profiles 与 Letters 是独立发布的阅读器。私有文档归配置的所有者，并以只读方式挂载。

一个应用使用独立仓库或子模块。Projects 的同一实现和服务承载多个项目，Travel 同样承载多份行程。具体业务记录保存在 Git 外，复用类型化数据、渲染器和资源权限。增加项目不需要复制应用仓库或页面系统。

产品由外部智能体、数据、界面三个实体构成。MCP、OAuth 2.0 委托、连接器与能力共同管理智能体与数据之间的关系。用户体验设计负责让界面中的数据便于理解和使用。这些关系能力不分拆为五种独立产品。即使两边都采用 coding agent，开发身份与业务身份也要隔离。日常账号与授权管理在受保护的网页中完成，维护 CLI 负责引导或故障处理。

## 选择工作流程

### 业务数据边界

真实业务操作由独立、已获授权的用户或外部业务智能体，通过归属应用的受控业务 API/MCP 完成。维护者不得通过直读文件、应用 CLI、SQL、curl、高权限后端或不受限的协助智能体生成、修改或清理真实数据。不得使用私人存储作为测试夹具。

维护者可以使用隔离的合成夹具，读取脱敏健康状态、协议跟踪、审计断言、版本和服务生成的完整性摘要。真实端到端测试记录的创建、变更与清理由指定业务执行者通过 MCP 完成。演示失败时，维护者不得代写记录来补救。保留归属应用的校验、并发语义、schema 兼容性和数据所有权。

私人运行记录、导出、备份、凭据及正文不得进入提交或测试夹具。实现 schema 修改或迁移程序，并不授权维护者对真实业务数据执行该程序。

### 仓库协作

按[贡献指南](../../CONTRIBUTING.md#简体中文)分配管理员、maintainer、外部贡献者与 agent 的责任。管理员和 maintainer 可在负责范围直接实现、验证、提交并推送；外部贡献者使用 issue 和 PR，由 maintainer 或管理员评审。Agent 遵循发起者的流程和已有授权。改动前确认所属仓库、发行分支、合同章节、验收条件和检查计划，提供实际证据及明确结果；敏感合同和生产发布由管理员把关。

应用实现与测试提交到应用仓，先发布应用改动，再把最终公开发行 SHA 固定到平台；外部贡献先合并子 PR。验证原生界面与平台的实际组合，在任务交付或 PR 中分别记录源码发布、发行准备和部署验证结果。

### 产品与代码变更

每项需求按以下顺序完成。

1. 先更新归属应用的 PRD，再更新路线图，之后才修改实现。跨应用变更还要更新平台文档。文档篇幅与改动规模相称。
2. 实现所需的应用、平台、适配或 schema 变更。优先复用有效接口，必要时扩展或替换以达成任务，保留无关系统。
3. 变更平台版本时，同步根 package、lockfile 及中英文 PRD 和路线图。保留历史发布行，同一变更的实现、测试和部署使用同一版本。独立应用遵循各自的版本策略。
4. 按行为选择检查。PRD 改动通过工作台阅读器回读。导航改动运行 `node --test tests/system-navigation.test.mjs tests/app-launcher.test.mjs` 并走通受影响的路径。集成变更运行 `npm test`。完成源码和浏览器验收后再构建受影响的镜像。单纯更正文档无需重建应用。
5. 验证后提交，只暂存该需求的文件。涉及子模块时先发布子仓，再提交父仓指针和集成改动。保留无关工作变更。管理员和 maintainer 可按已有授权直接推送；外部贡献使用 issue 和 PR 流程。
6. 任务针对本地自托管安装时，在指定环境部署已验证的运行行为改动，并检查实际入口后再报告完成。SaaS 服务按发布需要及目标环境的发布规则部署。只重建受影响的服务。未影响运行行为的文档或源码改动可直接交付。源码 PR 记录本机或 staging 证据，生产发布需要另行执行时明确负责人。报告提交、验证、评审及部署结果。

小改动验收通过后直接交付。可选顾问、无关测试、附带美化或已决定的设计不能阻塞交付。缺失证据要具体说明，避免为此自动启动所有测试。

对 schema 或迁移工作，用合成迁移夹具验证，并为有权执行者记录可回退的线上步骤。保留现有记录和应用承诺的兼容性。提交源码与合成测试，真实迁移后的私人记录留在 Git 外。

### MCP 工具配套技能

每个公开的 MCP 工具须关联真实业务技能并说明该操作。一个技能可覆盖同一应用的相关工具，明确权限边界、类型化输入、前提、写入与重试规则以及回读标准。在能力发现结果中发布当前授权范围内的技能关联，并支持受控读取。匿名指南只提供公共技能。新增或改名工具时补覆盖检查。不得把本高权限维护技能当作业务客户端说明，也不得改造外部 harness 强制注入技能。

### 外部客户端验收

涉及业务 API、授权或 MCP 时，先读[验证方案](../../docs/VERIFICATION.md)。完整线上证据包括真正隔离的独立 Paseo Codex 业务智能体，以及物理手机上独立运行的第三方智能体 App。文档协助者、高权限编码子智能体、直接运行 CLI/curl、模拟 MCP 响应、模型 API 调用或智能体自述，都不能替代这些验证。

协议和业务授权检查应在外部业务智能体的控制范围之外完成。普通业务工具不开放 shell、SQL、任意文件或代码访问、部署或备份密钥。记录实际 provider、客户端身份及脱敏的已提交结果。对前提不足和未执行项目如实标注；文档交付本身不能证明服务已实现或手机已连接。

### UI/UX 设计与修改

同一种业务功能共用一套界面，输入采用经过校验的不同数据。复用渲染器、组件、样式和交互状态，避免为每个项目、用户、地区或提供方复制页面系统。差异留在类型化数据投影和边界清晰的适配器中。获准设计已经移除的控件不应通过附加界面继续保留。平台级复用原则无需无关应用共享同一个运行时库。用多份数据验证同一组件，包括缺字段和提供方差异。

遵循已批准的页面范围，包括登录、工作台、管理、PRD 集合、应用和项目。复用现有页面和组件，仅在用户明确要求时增加独立页面或导航入口。

界面与交互工作遵循 [Praxis UI/UX 指南](references/ui-style-guide.md)。先明确任务、入口、可见结果和返回或恢复路径，再选择启动台、集合、阅读或编辑模板。用一条有代表性的路径验证改动。共用原生视觉语言，各类页面按任务选择布局。Reminder 是留白和集合页侧栏的基准；使用该模板时保留本地字号和行高，对照实际渲染的品牌区与首条目位置。工作台启动器可以使用居中图标网格和紧凑账号行。遵循用户明确的选择，以及归属应用的行为、语言和访问边界。样式与组件由应用维护，勿据此重做其他应用或引入平台共享运行时依赖。

接入身份、API 和 MCP 时保留应用已经认可的展示和交互。调整传输层时，用同一份合成内容对照原生和受管界面的主栏、视图语义和既有控件。导航名称相同不能证明两端功能一致。

开放写入前先用代码定义界面依赖的数据合同。数量、单位、时间段和状态使用经过校验的数值或枚举。文案标签、格式和缺失显示由代码负责。只有明确指定为自由文本的标题、备注等字段才接受文字。来源观察、验证状态和审计解释与短事实字段分别保存。接口限定到具体对象和允许修改的字段，在服务端拒绝未知字段、错误类型和放进结构化字段的说明文字。不得以整份 JSON 替换规避边界。保持界面行为，由业务智能体填写获准的数据。提示词不能替代服务端强制校验。

### 图片性能

图片缓存是通用要求。涉及图片响应或部署时，查阅[图片缓存合同](references/image-caching.md#图片缓存合同)。在实际拥有图片的服务端应用缓存策略，网关保留校验信息。先检查图片是否已内联或本机保存，再决定是否增加网络机制。独立应用维持自包含，共同的指导不要求共享运行时。

### 服务与可恢复存储

平台核心后端统一使用 `core` 名称，命令优先使用 `npm run core`、`npm run core:admin` 和 `npm run core:stack`。旧 `business` 命令名和受管组名继续作为兼容别名。保留各安装原有的项目名、源码与配置路径、应用业务 API 及私有数据绑定。

部署、换机或迁移存储时，阅读[Docker 运维手册](../../docs/DOCKER.md)和[存储合同](../../docs/STORAGE.md)。当前 Compose 与蓝绿槽操作使用[受管部署指南](../../docs/MANAGED-DEPLOYMENT.md)中的命令。Docker 引擎不可用时保留现有可运行服务，验证替换环境后再切换。

新应用在构建与部署前填写[首发记录](../../docs/DOCKER.md#新增应用首发)。记录空白或首次使用状态、数据归属、桌面及手机上从应用点击 Home 返回工作台的实际结果，以及上一槽回滚预期。遵循[应用标准](../../docs/APP-STANDARD.md)，先更新英文产品文案和文档，再同步中文。

应用维护本地工作数据，存储协调器负责一致快照和加密副本。读取私有存储配置确认实际活动来源，切换后避免误用旧检出目录的默认来源。Reminder CLI 测试使用隔离实例。SQLite 使用在线备份，保留 Slides 创作状态，单独报告浏览器导出和原音频的覆盖。不得把云盘或 NAS 目录同步当作活动数据库的安全合并。

保持一个活动 writer，验证向新空目录恢复，并明确完成交接。源码提交、私人导出、供应商密码和恢复密钥分别保管。更换存储供应商需完成复制、完整性检查和试恢复，保留旧目标。真实远端验收、合成检查和未配置凭据分别记录。

## 授权与交付

已有授权范围内的读取、编辑、测试和必要的本机服务操作直接继续。只有在缺少关键信息或决策且无法从仓库和对话推断时，才向用户询问。高权限访问不扩大请求范围；对外发送消息、公开发布、推送和建立远程资源均须获得对应授权。

代码注释、内部错误和 CLI 输出使用英文。UI 依照当前应用语言；用户原创内容保留原文。界面只呈现有助用户采取行动的实现或诊断信息。

以可观察的结果、相关验证和本地提交完成代码需求。业务数据操作由指定外部执行者处理，维护者只报告允许披露的脱敏证据。精确说明未核验的部分。技能中描述的后续路线图并不构成执行授权。
