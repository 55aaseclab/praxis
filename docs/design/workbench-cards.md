## 目标

让实际做事的人理解结果、核对依据，并决定何时处理。每张卡应帮读者少找一次资料、少重建一次上下文，以[员工注意力需求](../PRD.md#保护员工的注意力)为产品依据。

阅读参考：[《置身钉内》](https://gist.github.com/horaceho/4be04df73b1f1ede458ad5cec2b94132)。文中关于收发双方立场、已读规则和卡片过载的讨论用于启发设计；下文是 Praxis 自己的产品选择。

## 卡片结构

保留底栏现有的 Apps / 待关注单图标开关，内容始终顶部对齐。主要区域显示一张便于阅读的卡，提供有限队列、左右键和明确的前后切换按钮；可以打开列表定位事项，避免无止境的信息流。

| 层次 | 内容与作用 |
| --- | --- |
| 来源与出现原因 | 说明所属应用及真实原因，例如自己设定的提醒、明确分配给自己审阅的工作项。 |
| 结果或问题 | 标题具体。需要判断的卡片写清问题，避免重新丢给人一个含糊任务。 |
| 有用的预览 | 展示有来源的简短结果或待选方案，保留原文语言；没有预览就留空，不编造。 |
| 按需查看依据 | 展开对应原始资料、版本和未确认事实，提供有权限的原文入口。 |
| 一个主要动作 | 明确进入所属应用，例如「打开简报」「打开提醒」「查看选项」。 |
| 个人处理 | 「稍后看」「收起这一版」只改变自己的呈现，可撤销。 |

原型使用修订后的野外调查简报、个人提醒和走访时间选择三份合成示例，展示目标交互及拟新增的数据，不连接生产服务。

## 由使用者掌握节奏

- 看见、滚动、滑过和打开，都不表示接下任务、认可结果或完成业务记录。
- 「稍后看」只改变这张卡何时向自己出现，不改截止日期、分配关系或共享状态。显示所选时间，并提供撤销。
- 「收起这一版」是可撤销的个人动作。后续更新按同一业务对象合并，更新十次仍只是一张当前卡；新版本可在使用者下次选择的查看时段出现。
- 新内容到达时，保留正在阅读的卡和键盘焦点，提示可查看的更新，不自动替人打开。
- 语言及个人显示偏好统一放在 Settings。例行结果等待读者主动查看；立即打断须有事先约定的规则、具体影响及有权解决的人。
- 排序依据是来源事实和用户偏好，职级、未读状态和推测的空闲程度不构成紧急性。
- 允许普通留白。空状态只说「这里暂时没有新内容」，提供应用入口，不打分、不设置连续打卡、不催清空队列，也不因做完工作而发奖励话术。

阅读、暂缓和个人显示偏好与共享业务进度分开。工作流留痕可以记录获授权并已提交的操作、来源版本和明确决定；私人浏览不成为团队绩效动态。安全访问日志遵循独立的权限和保留规则。

## 视觉与交互

沿用工作台的灰底、白卡、原生系统字体和松绿色操作入口。来源色只标识上下文，日期采用平实文字；不把每个截止日期都做成警报。保留现有导航及所属应用的结果界面。

标题清楚、预览紧凑、来源信息稍弱，依据按需展开。一张卡保留一个主要动作。桌面和手机都有清楚焦点、44 CSS px 点击区域和正常纵向滚动；横向手势是可选路径，按钮和键盘提供等价操作。

「打开」进入所属应用的具体对象，Home 返回原卡及安全的滚动位置。未来如增加有实际影响的修改，必须使用所属应用的类型化、版本校验和授权操作，并有明确意图和回读。

## 数据与实现边界

当前卡片接口只聚合 Reminder 和 Projects，提供对象身份、标题和日期，以及提醒旗标或项目的 domain/review 字段，尚无结果预览、依据片段、对象 revision 和个人稍后/收起存储。

完整方案需要：

1. 由所属应用提供稳定对象身份、版本、有来源的预览、明确出现原因及经过授权的依据引用。标题、预览和数量继承原对象权限，模型推测不成为来源事实。
2. 按用户、对象及版本保存的个人呈现偏好。不得用修改提醒日期、完成或删除记录来代替「稍后」和「收起」。
3. 清楚的更新边界：合并对象版本、保留焦点、让读者决定何时展示新内容。
4. 既有的来源导航与授权规则。接入其他应用须显式集成，管理员专属应用不会通过卡片自动向普通成员开放。

实现时可先复用现有卡壳、来源链接及导航，再完成数据投影和个人偏好合同。本文保留完整目标，原型中的预览与个人操作属于提议中的能力。

## 状态

| 状态 | 呈现 |
| --- | --- |
| 加载 | 安静的占位及加载说明，不编造事项数量。 |
| 空 | 简短的中性文案与应用入口。 |
| 部分失败 | 保留本次成功验权并读到的卡片，说明暂未完成的更新，可重试，不泄露被拒绝的资源。 |
| 错误 | 说明暂时无法读取并提供重试，不把未核实内容显示为最新结果。 |
| 失去授权 | 清除受保护的标题、预览、数量及依据，丢弃上一身份迟到的响应。 |
| 版本变化 | 用事实提示可用更新；旧内容不能悄悄成为对新版本的确认。 |

## 后续实现的验收依据

- 打开、翻页或收起，不改变共享业务记录。
- 个人「稍后/收起」在约定的刷新和设备范围内保留，普通产品接口不允许其他成员查询；界面说明原事项日期未改变。
- 同一对象的多次更新只形成一张卡，刷新不顶走正在看的卡、不抢焦点。
- 不必打开多个无关应用，就能理解有用的结果、明确的问题及对应依据。
- 仅改变发起者职级时排序不变，规则触发的打断能说明具体影响。
- 来源链接定位到具体对象，Home 恢复阅读位置；桌面、手机及中英文均走通。
- 缺上下文、部分刷新、资源拒绝、版本过时各有清楚状态。身份失效清除内容，不宣称当前系统尚未提供的跨设备瞬时撤权。
- 评估用户自愿参与的合格结果处理用时、查找依据的时间和可避免的打扰；清空率、阅读速度和个人响应时长不作为员工评分。

原型检查覆盖布局、导航、局部示意操作和状态；持久化、服务端权限、去重及真实业务操作留待实现验收。
