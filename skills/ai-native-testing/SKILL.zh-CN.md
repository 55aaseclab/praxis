# AI-native 测试

简体中文 · [English](SKILL.md)

CLI 与证据格式见[操作说明](../../tests/ai-native/README.zh-CN.md)。场景、人设及情境抽样见 [campaigns.mjs](../../tests/ai-native/campaigns.mjs)，为角色准备任务时仅传递其应知背景。平台要求是 [Praxis PRD 的 ANT01–ANT10](../../docs/PRD.md#长期-ai-native-testing)。

主控负责协调，业务角色使用应用，Maintenance 修改代码。三个团队、九位持久业务角色及各自私有知识保持分离。研究组织包含导师/学生研究组、一位产品工程师、一位市场人员、一位财务/支持人员；业务工程师不是平台 maintainer。家庭恰好三人。投资本金与交易均为合成；交易前必须配置市场、期限及信息截止时点。

所有派发经框架 CLI：发现精确模型，在调用 Paseo 前持久预留全局 worker 单槽。主控用 GLM-5.3-Flash main，worker 用 GLM-5.3-Flash worker，Maintenance 用 GPT-6.1-Sol ultra 和默认上下文。保留正常客户端工具，应用服务边界的 grants 约束业务权限。不直接启动 agent、另开并行助手或限制 worker token。串行执行不能证明多用户负载能力。

配置固定 `fullAccess: true`、`communication: "paseo-send-message"`。OpenCode 用 build+auto_accept，Codex 用 full-access；普通工具权限不重复问人工，真正的问题和逐次 Maintenance 确认仍须问。派单、汇报和追问使用 Paseo send_agent_prompt/agent.send/公开 paseo send，不读其他角色工作文件或反复拉日志/时间线代替通信。业务结果留在所属应用，新任务/恢复执行前仍须占 worker 槽。

先检查状态、未完成派发与覆盖。回收已确认派发的空闲会话，但空闲不等于成功。独立回读授权结果或取得服务断言后提交验收证据。保留失败尝试、原角色和随机情境。修复复测优先，必须对应实际运行的修复版本。完整重演另用独立配置的合成测试状态，不能删除长期团队历史来重置。

验收通过后安排下一轮。目标和带种子的情境变化引导自主操作，不逐步编排或制造同意。应用记录保持权威。发现真实能力和操作技能，缺失操作如实报告，不用聊天/文件替代。Polaris 是经授权只读观察器，不是调度器。情报与投资保留来源及发布时间证据。

产品失败后，构造最小合成技术复现。`repair` 仅接受技术字段。用 `approval-request` 准备问题，通过正常 question 工具或 Paseo 会话向人工提问，等待实际明确批准/拒绝。只有收到人工答复后才用 `approve` 记录问题标识、原答复及用户回复引用。不得自答、把沉默或澄清当批准、自行修代码或绕过框架。每次介入都需要自己的人工答复，预留时单次消耗，包括结果不明的情况；扩大范围须新提问。不使用签名密钥。回执是会话审计记录，不是防任意客户端伪造的密码学证明。不向 Maintenance 传课题、目标、业务正文、截图、讨论、凭据或原始工具输出；人工审阅须确认语义脱敏。

建号、建团队、同意、授权及所有业务操作仅经公开支持的产品界面、已文档化公开 API 或公开 MCP。即使是合成账户，也不调用内部/未公开端点、管理员 bootstrap、SQL 或服务端文件补齐缺失流程。实际发现并报告公开能力缺口，保留正常客户端工具及文档化本地框架命令。

不明派发无限期保留占槽，通过不透明 Paseo label 核对新建会话。丢失 send 回执不能凭空闲判断，应由 人工根据真实队列/时间线证据在 Paseo 明确确认核对结果。不因超时自动释放并重复执行。暂停阻止新派发，保留在途工作，不中断角色。等待人工确认、客户端凭据、能力证据或投资参数时，简短报告阻塞并结束本轮。加载此技能不授权创建周期调度、生产部署或操作既有业务数据。
