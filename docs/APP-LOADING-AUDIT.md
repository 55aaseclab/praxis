## 经审核的模块合同

应用根目录固定文件 `praxis-integration.mjs` 导出 `createIntegration({z})`，factory 返回包含 `schemaVersion: 1` 与正式 `appId` 的集成定义。可引用本应用源码中经审核的 helper。平台仅加载选定、固定提交的本地源码，不接收调用者指定的模块路径或远端可执行 URL。非法或重复身份、slug、工具、scope、动作及不安全路径在激活前拒绝。

`web` 声明 `slug`、`policy`（`grant`／`platform-admin`／`document-owner`）和 `kind`（`proxy`／`static`／`private-documents`），以及对应的源码相对目录／资源和默认原生端口。默认值只说明支持的绑定，不证明后端已运行；实际目标、所有者身份和私有挂载由安装覆盖项决定。应用纯路由 hook 只看方法、路径和查询，可请求已声明绑定、相对路径或资源检查，不自行选择绝对上游或转发凭据。

`business` 声明 adapter ID、支持动作／scope、限定创建、操作、类型化工具、技能与说明；操作的写入性质与授权动作分开。应用 hook 校验／转换请求、结果、错误，声明附加验权、授权的跨应用读取、有限签名字段和事件采集。`prepareInvocation(request, ctx)` 可返回正规化请求与已声明附加断言；当前应用限定的 ctx 提供安全身份事实、业务成员角色、`hasAction`、`canReadSubject` 和声明的授权读取，不暴露令牌、密钥、AuthStore、任意 fetch 或 SQL。签名保留字段始终归 bridge，附加权力由平台原语生成并复核，不接受请求自行宣称。

安装与存储采用同一归属边界：业务调用者不能提供任意执行命令；描述使用已审核源码／默认值和已解析的私有绑定。发现不启动服务、不创建业务记录、不改变授权。

## 抽离时必须保留的行为与权限

- Knowledge 的旧资源边界和原生阅读器。
- Lattice 的原生模板、创作／渲染权限、旧 deck 视图、任务授权和有界媒体／产物合同；已禁用视频引擎保持禁用。
- TingProof 的任务壳／公共资源、分段边界、独立整项目权限及服务端 submit 判定。
- Polaris 的文件系统观察器、安全请求头和内部 Trace 路径阻断；不引入执行器、攻击 pack 或 live adapter。
- Calendar 的授权 agenda 投影及完整静态模块依赖。
- Letters／Profiles 的所有者原件读取、no-follow 文件处理和撤权栅栏。
- 所有应用既有 schema、幂等、来源／输出版本、一致存储及原生导航。

所有消费者共用不可变 registry；兼容导出只能是 registry 的派生视图，不保留第二份硬编码目录或 fallback switch。写入新策略时拒绝未支持能力；读取合法已存策略时安全忽略停用能力，不删除记录或使无关授权失效。停用隐藏入口／工具并拒绝访问，保留数据、历史及回滚能力。观测维度来自已知安装身份，任意调用者名称仍归安全 unknown。

## 实现边界

`src/app-integrations.mjs` 校验并冻结已安装定义。身份授权、业务桥接、MCP/技能、HTTP 网关、卡片/数据清单、观测与前端目录事实使用同一个注册表。运行时导入不得把浏览器或 MCP 参数作为模块路径。`PRAXIS_APP_SOURCE_ROOT` 是运维/测试显式指定源码根目录的选项，不是对外服务参数。

应用自己的 `praxis/` 辅助模块保留原生路由例外、类型化 schema、技能、旧版 UI/资源以及 runtime trace 归一化。部署模块拥有原生 `Dockerfile.praxis`、本机 Compose 配方及可选的源码构建步骤。`node scripts/generate-compose.mjs` 重新生成仓内安装快照及 Docker 源码上下文白名单；`--check` 检查两个产物的漂移。静态资源、图稿及可选构建输入来自已安装的应用声明。平台基底描述初始化、Core 和工作台；每个已安装应用提供自己的服务与卷定义，继续保留卷身份及安装环境既有项目名。发现配方不会启动服务。

仅供运维使用的存储/部署 hook 接收必要的私有路径元数据及经过校验的文件/挂载原语，只在显式安装/恢复命令中运行，与受限的业务调用 hook 分开。应用声明自己的格式、工作数据路径、迁移输入、验证器及清单投影，平台继续负责规范路径/no-follow 校验、SQLite 一致性快照、写者栅栏及可恢复的安装变更。带旧名称的 CLI 别名和既有环境的 Compose 快照继续作为兼容入口，不提供第二套运行时能力注册表；Polaris 兼容入口只支持安全的只读查看器。

`config/installed-apps.json` 中的内置集合是显式安装选择，并固定已审核的公开源码。产品例子、合成夹具、历史发行台账及私有部署覆盖可以出现应用名称，这些内容不负责按应用身份分派行为。新原生应用提供模块、Dockerfile 与安装配方后，通过通用命令重新生成安装快照，无需改平台代码。

### 激活与保留配置

服务启动时激活经审核的注册表；安装源码变化后重启受影响的平台服务。停用时先停止应用写者，保留备份、数据及私有设置。移除安装源码，并在私有 Core `inactiveApps` 中明确列出保留配置的 adapter ID。Core 仅从分派中排除这些显式停用、已移除的 adapter，不重写其配置；未登记为停用的未知 adapter 仍校验失败。已有授权及历史保留，但不能授权访问停用应用。重装时移除停用标记，一并激活审核后的源码与原设置。元数据/供数响应仍可刷新，但用户请求期间不会因文件被改动而热加载可执行代码。

源码演示命令同样加载应用自己的 `deployment.demo` 配方。平台管理固定提交的源码归档、私有临时 HOME/数据、白名单环境及清理；应用专用的依赖、合成初始化、构建和启动步骤归应用维护。未提供演示配方时明确显示不可用，不冒充后端已存在。
